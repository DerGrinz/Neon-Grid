## GAME CONSTANTS (use these exact values)

```typescript
// constants.ts
export const BOARD_W = 10;
export const BOARD_H = 20;

// DAS / ARR (Delayed Auto Shift / Auto Repeat Rate)
export const DAS_MS = 167;
export const ARR_MS = 33;

// Soft drop multiplier
export const SOFT_DROP_MULT = 20;

// Gravity table (ms per row drop) — simplified Tetris guideline
export const GRAVITY_MS: Record<number, number> = {
  1: 1000, 2: 793, 3: 618, 4: 473, 5: 355,
  6: 262, 7: 190, 8: 135, 9: 94, 10: 64,
  11: 43, 12: 28, 13: 18, 14: 11, 15: 7,

  SOFT_DROP_PER_CELL: 1, HARD_DROP_PER_CELL: 2,

```

## TOUCH CONTROL THRESHOLDS

```typescript
const SWIPE_MIN_DISTANCE = 30;        // px
const SWIPE_MAX_DURATION = 300;       // ms
const TAP_MAX_DURATION = 200;         // ms
const TAP_MAX_DISTANCE = 10;          // px
const LONG_PRESS_MIN_DURATION = 400;  // ms
const HORIZONTAL_BIAS = 1.5;          // |dx| / |dy| ratio
```

Conflict resolution:
- Vertical swipe ONLY if |dy| > HORIZONTAL_BIAS × |dx|
- Tap ONLY if total movement < TAP_MAX_DISTANCE AND duration < TAP_MAX_DURATION
- Hold (move + auto-repeat) triggers after pointer is held stationary at edge 
  of swipe for DAS_MS, then repeats every ARR_MS

### Color Palette (CSS variables in theme.css)
- `--bg-deep`: #05060F
- `--bg-grid`: #0B0E1F
- `--neon-cyan`: #00F0FF
- `--neon-magenta`: #FF00E5
- `--neon-violet`: #8B00FF
- `--neon-green`: #00FF9D

- `--neon-orange`: #FF8A00
- `--neon-blue`: #2979FF
- `--text-primary`: #E8F4FF
- `--text-dim`: #6B7BA8

### Tetromino Colors
- I → cyan, O → yellow, T → violet, S → green, Z → magenta, J → blue, L → orange
- Glow: `box-shadow: 0 0 12px currentColor, 0 0 24px currentColor`

### Typography
- Headings: Orbitron, uppercase, letter-spacing 0.15em
- HUD / numbers: Rajdhani or JetBrains Mono (monospace for digits)

### Layout (mobile-first, 375–430px target)
- Portrait locked via manifest
- Playfield ~85% viewport width, centered
- HUD top: Score / Level / Lines
- Hold + Next queue: right of playfield (or below on narrow screens)
- Bottom: optional touch button overlay (toggleable)

PERFORMANCE PRIORITY (when in conflict):
Game loop FPS > Touch responsiveness > Visual FX
Drop chromatic aberration / screen shake / animated mesh on devices where 
they cause frame drops below 55 FPS. Respect `prefers-reduced-motion`.

### M2 — Game Engine (pure logic, no UI)
Deliver: `/src/game/` with engine.ts, tetrominoes.ts, bag.ts, scoring.ts, 
constants.ts. ALL functions pure and unit-tested with Vitest.

Concrete tasks:
1. `constants.ts`: export the GAME CONSTANTS block above verbatim
2. `tetrominoes.ts`:
   - Define all 7 pieces (I, O, T, S, Z, J, L) as 4 rotation states each, 
     represented as 4x4 matrices (or piece-appropriate bounding box) of 0/1
   - Export the SRS kick tables: one for J/L/S/T/Z (shared), one for I 
     (I has its own kicks). Each transition (0→R, R→0, R→2, 2→R, 2→L, L→2, 
     L→0, 0→L) defines an array of 5 [dx, dy] offsets to test
   - Reference: https://tetris.wiki/Super_Rotation_System
3. `bag.ts`:
   - 7-bag randomizer: shuffles all 7 piece types, dispenses one at a time, 
     refills when empty
   - Export `createBag(rng?: () => number)` for testability with seeded RNG
4. `scoring.ts`:
   - `calculateLineScore(linesCleared, level, isTSpin, isMiniTSpin)` returning points
   - T-spin detection helper using 3-corner rule:
     A T-piece lock is a T-spin if 3+ of the 4 cells diagonally adjacent to 
     the T's center are occupied. Mini T-spin if only 2 of the "front" 
     corners (the two corners on the side the T is pointing) are occupied 
     and 1 "back" corner is occupied.
   - Soft/hard drop scoring per cell traveled
5. `engine.ts`:
   - Pure state-transition functions: `spawnPiece`, `tryMove(state, dx, dy)`, 
     `tryRotate(state, direction)` (uses kick tables), `lockPiece(state)`, 
     `clearLines(state)`, `isGameOver(state)`
   - State shape: `{ board: Cell[][], current: ActivePiece, hold: PieceType | null, 
     queue: PieceType[], score, level, lines, holdUsed, lockTimer, lockResets }`
   - Functions return new state objects (no mutation)
6. Vitest setup: `vitest.config.ts`, test files alongside source as `*.test.ts`

Required test coverage:
- 7-bag dispenses exactly one of each piece per cycle (test with 100 bags)
- Each piece rotates correctly through all 4 states (snapshot test)
- SRS kicks: at least one known case per piece, e.g. T-spin triple setup
- Collision: piece against left/right wall, floor, stacked block
- Line clear: 1, 2, 3, 4 simultaneous lines, scoring matches table × level
- T-spin detection: T-spin single, double, triple, mini, false positive 
  (regular T-piece lock is NOT a T-spin)
- Gravity table values match constants

Verification:
- `npm run test` → all tests pass
- `npm run test -- --coverage` → engine files at >85% coverage
- No UI work in this milestone

After M2, output summary + verification, then ask: 
"M2 verified — proceed to M3?"

Concrete tasks:

   - Holds engine state, exposes actions: `move(dx)`, `rotate(dir)`,

3. `useKeyboardControls.ts`:
   - ArrowLeft/Right → move (with DAS/ARR repeat using DAS_MS/ARR_MS)
   - ArrowDown → soft drop (held = continuous)
   - Space → hard drop (single press only, no repeat)
   - ArrowUp or X → rotate CW
   - Z → rotate CCW
   - Shift or C → hold
   - Esc or P → pause
   - Cleanup all event listeners on unmount
4. Integrate hold (1 slot, swap with current, locked until next piece spawns)
5. Lock delay: piece on ground starts lockTimer (LOCK_DELAY_MS), resets on 
   successful move/rotate up to LOCK_RESETS_MAX times, then locks

Verification:
- Fully playable with keyboard on desktop browser
- Chrome DevTools → Performance: sustained 60 FPS during play

- Hard drop locks immediately + adds correct score
- Hold works once per piece, re-enables after lock
- Pause stops gravity and ignores input except resume
